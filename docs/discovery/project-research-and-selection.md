# 项目信息、个性化建议与申请时间表

- 依据：[2026-10-31 项目建议表陈述](../sources/business-brief-2026-10-31-value-and-projects.md)，以及此前动态选校、客户选择和递交确认的结论。
- 状态：用户已确认展示内容与基本选择需求；业务含义和信息维护细则继续讨论。
- 当前用途：梳理业务信息，不涉及采集工具、界面实现或首期开发范围。
- 核心职责补充：项目要求先查数据库，缺失时查学校官方网站，结构化入库后再使用；不要求顾问先查官网并逐条转述。申请系统由顾问手动操作，差异反馈给 AI 后按模型修改补充。具体任务依赖和业务影响关系见[自主工作需求](agent-autonomy-requirements.md)。

## 1. 项目共用信息与学生个性化判断（整理建议）

用户给出的字段中，学校、项目中英文名称、课程简介、学制、雅思要求、授课语言、特别要求、费用、截止和官网可以整理为项目资料。

匹配度、“为什么适合你”与客户是否申请，涉及特定学生与特定项目的关系。用户已确认把“申请机会判断”和“方向适合理由”分别说明，并用定性判断及依据表达。相同项目可以面向不同学生给出不同解释，不将这些判断填作学校官方标准。“方向”具体指学校的专业分类还是顾问面向学生的建议方向，后续确认。

用户已澄清：交付选校表后的反馈是客户是否选择项目，不设置学生对 AI 分析内容的单独认可环节；选择项目不等同对每条分析作背书。

建议把项目资料关联到具体申请季和所核验的来源；匹配判断另外记录其所依据的学生背景与需求。这是信息组织建议，未形成正式模型。

## 2. 用户已确认需要的内容

- 方向、学校、项目名称、英文名称。
- 匹配度、课程简介、为什么适合你。
- 学制、雅思要求、授课语言、特别要求。
- 学费、申请费、申请截止、官网。

费用币种、学费按学年还是整个项目、截止对应哪一轮等细节，需在实际信息中明确。当前不填造学校、费用或日期。

原“匹配度”按用户确认分成两方面的业务解释：申请机会判断、方向适合理由，均为定性判断及依据，不生成录取概率百分比。具体表头与展示形式未定，不因此开展界面设计。

## 3. 申请材料要求

用户明确希望收集学校和项目的材料要求，例如 PS 字数要求。

已确认取得和使用顺序：查数据库 → 缺失时查学校官网 → 结构化入库 → 使用。以下为继续细化的信息组织建议：

- 针对具体项目和申请季记录材料要求，自动采集的官方依据关联学校官方网站；顾问反馈的申请系统差异另保留反馈依据。
- PS 可记录是否需要、题目或需回应的内容、长度要求及计量单位、格式和其他限制；具体有无这些限制以核验结果为准。
- CV、推荐信、成绩及其他材料可分别记录要求，避免把客户通用收集清单直接当作每个项目的完整递交要求。
- 保留来源位置和核验日期；无法确定的要求标为待核验，信息变更时指出影响到哪些已选项目或文书。
- 通用业务约束引用库中结构化项目要求，长度等参数从已记录的要求取得；缺项查官网后先入库。申请系统差异由顾问反馈，不要求 AI 自动登录核查。
- 查库和官网后仍无明确要求时，先完成不受影响内容，列明待核对要求供顾问补充；“没找到限制”与“官方明确没有限制”分别记录（用户已确认）。

以上为待确认的业务细化，不宣称所有学校都有相同要求，也没有在本轮执行外部资料收集。

## 4. 申请时间表与客户选择（用户确认）

- 按申请截止日期排序。
- 显示剩余天数。
- 让客户选择是否申请。
- 客户选择意向用于安排准备；正式递交前仍对拟递交项目和最终材料留一条明确确认（R11 确认）。

待确认的建议：

- 客户未作选择与明确不申请分别表达。
- 一个项目存在多轮时，显示具体轮次或正在考虑的截止，而不是混用多个日期。
- 原文截止时点和时区、尚未确定或尚未公布的截止分别记录；剩余天数以明确可解释的日期口径计算，未知截止不填为 0 天。
- 学生经历、意愿和资料变化时可以修订项目建议与选择，沿用用户已确认的动态调整方式。
- 申请意向与递交确认已明确区分。用户接受客户改变方向或项目，配合调整，不把变更本身设为必须加价或重谈条件；不同申请季等其他情形尚未讨论。

## 5. 与咨询和交付的关系

- 初次咨询根据七类基础背景提供第一版学校专业建议，可使用上述项目资料作解释。
- 后续微信职业探索与经历挖掘为匹配判断提供更多依据，必要时调整建议。
- 客户选择意向用于安排准备（用户已确认）；准备的具体时间顺序和优先级按后续业务安排确定。
- 每个已选项目都准备 PS；区分通用初稿与项目最终递交稿，最终稿明确项目并分别编写。最低标准来自学校官网并维护入库，已达标项目优先准备，组内按截止日期排序；未达标可能与客户沟通放弃。客户时间表仍按截止展示。
- 未达标项目是否继续由顾问和客户人工决定，记录未达标原因与最终选择；AI 不自动取消项目，也不因决定继续而将其改记为已达标。
- 学生背景事实共用，通用 PS 初稿按方向分别准备，最终稿逐项目定制；允许直接准备项目稿，方向初稿已有则参考、没有也可依据学生事实和项目要求直接准备，后续沿用中文核对、英文生成和最终确认流程。
- 项目要求为文书定制、质量核查和时间规划提供依据；完成方式和实际确认流程仍按各业务环节分别记录。

## 6. 变化和修正（用户已确认）

- 客户换方向或项目时配合调整建议与准备，不单因该变化自动要求额外协商。
- 已给客户的信息变化或有误时，先核验来源，主动说明变化及受影响事项，再调整材料和计划，并保留修正说明。
- 客户迟交材料或未回复影响准备时，说明缺项、所需时间与延迟影响，按剩余时间调整可完成范围并保留沟通记录。
- 学生背景、成绩或项目要求的变化由顾问反馈或手动平台修改；当前继续梳理业务影响范围，尚不定义事件与任务触发机制。
- 影响范围已确认：个人变化涉及本人及相关项目；项目要求变化涉及所有适用该要求的相关学生，按变更内容评估材料、文书、判断与安排。受影响不等于全部必须重写。
