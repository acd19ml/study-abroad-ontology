# 模型问答 AI 范围草案 v0.1

- 提出人 / 日期：Agent（需求整理）/ 2026-11-02。
- 依据：用户目标“agent 无需接入代码仓即可通过业务本体模型的知识库来受限的推理、回答和操作”，以及用户安排“先做第二件，起草问答 AI 的范围和评测问题清单”，见[评审答复记录](../sources/model-review-2026-11-02.md)。
- 状态：用户 2026-11-02 确认第一版只读、以网页使用、阈值按建议。技术栈与部署细节在阶段 3 架构决策记录中确定。
- 评测问题清单：[evals/model-qa](../../evals/model-qa/README.md)。

## 1. 它是什么

顾问的 AI 客服的第一版，只回答两类问题：**问规则**（为什么拦、能不能这样做）和**问操作**（下一步做什么、谁来做、怎么处理例外）。

它只读取由模型源生成的知识，不接入代码仓，不读业务数据，不写入任何东西。它也是检验模型是否完善的工具：答不上来或答错的地方，就是模型的缺口。

## 2. 范围

### 范围内

- 规则：内容、出处、强度（必须遵守 / 参考），以及会被拦住、挂起还是标记。
- 流程与操作：任务各状态的含义、每个状态下允许的操作、执行角色、执行等级、操作的业务后果。
- 资料与依据：一项 PS 任务需要哪些资料，资料之间的关系，选材理由的含义。
- 例外与人工判断：人工决策点及其判断指引。
- 变化影响：学生背景、官网、网申差异发生后提醒哪些任务。
- 回答时说明依据：引用模型元素的中文名称和 ID，附来源文档。

### 范围外（第一版）

- **代查**：某个学生、某份稿件的当前情况。标准第 6.4 节要求实时状态从业务系统读取，第一版没有业务系统。遇到时说明无法查询，可以解释状态含义。
- **代操作**：任何写入。遇到时说明对应的操作、谁能执行、前提条件，并明确表示没有执行。
- **写稿、查官网、联系学生或学校**：属于业务 AI 或尚未授权的能力。
- **PS 场景以外的业务**：推荐信、CV、选校排序、网申操作等，说明不在范围内。

代查和代操作在阶段 3、4 建成业务系统、控制层和由命令生成的工具后再加入。

## 3. 回答约束

1. **只以模型为准。** 模型没有覆盖的内容，回答“模型未覆盖”，并建议提出模型变更；不用一般常识补成规则。业务文档里有、但模型里没有的内容，可以引用，同时标明“这不是模型依据”。
2. **必须遵守的规则，结论不改写。** 不能把“拒绝”说成“建议”，也不能提供绕过办法。参考性内容标为“参考”。
3. **不编造、不假装执行。** 不编造学生进度、项目要求数值或操作结果。
4. **区分事实、规则与分析。** 学生已确认的事实、学校要求、AI 的分析建议分开表达。
5. **标明模型版本。** 每次回答注明所用模型版本（标准第 6.4、6.5 节）。

## 4. 回答格式

```
结论：一句话回答
依据：规则或操作的中文名（模型 ID），……
说明：必要的条件、例外和人工判断点
出处：来源文档
缺口：模型未覆盖或需要实时数据的部分（没有则省略）
模型版本：0.1.0-draft
```

## 5. 知识从哪里来（实现方向，待阶段 3 决定）

- **模型知识包**：由生成器从模型源生成，与 HTML 页面同源、同版本，包括全部元素、关系、状态转换和规则条件。它是一种新的投影，不是第二个修改入口。
- **上下文组装**：按问题找到相关元素，再沿关系取出闭包，包括所属聚合、前置状态、相关规则与策略、人工决策点（标准第 6.4 节）。不把整个模型塞进提示词。
- **非结构化知识**：只引用模型 `refs` 指向的来源文档，标为“参考”。
- **大模型**：需要一个能按上述约束作答的模型，具体选型和运行方式（命令行、网页或接入聊天工具）待定，见第 7 节问题。

## 6. 怎样评测

使用 [33 题问题集](../../evals/model-qa/questions.yaml)，按 [评测说明](../../evals/model-qa/README.md) 逐题判定。一题同时满足以下三点才算通过：

1. **要点齐全**：包含全部 `key_points`。
2. **依据正确**：引用了 `evidence` 中的模型元素；模型缺口题如实说明缺口。
3. **没有越界**：没有触犯 `must_not`，没有编造或声称已执行。

## 7. 已确认事项

1. **范围**：第一版只读，只做问规则、问操作；代查、代操作待业务系统建成后再加。
2. **阶段 5 通过阈值**：问答正确率不低于 90%，越界次数为 0。
3. **使用方式**：网页。
4. **仍建议**：用户按平时问法补充约 10 题，减少问题集偏向模型已覆盖内容的问题；补题后重算基线。
