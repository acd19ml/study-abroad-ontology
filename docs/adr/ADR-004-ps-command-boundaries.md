# ADR-004：PS 场景命令的四类边界、扩展点与人工介入

- 状态：提议
- 日期：2026-11-02
- 相关模型元素：全部 22 个命令；`agg.ps.task`、`agg.ps.student_context`、`agg.ps.program_knowledge`；全部规则、人工决策点与策略
- 依据：实践标准第 6.1、6.3、7.1、7.2 节及第 8 章阶段 3；用户已确认的执行等级相关答复见[评审答复记录](../sources/model-review-2026-11-02.md)。

## 背景

阶段 3 要求为每个命令确定业务、确定性、人机、生成四类边界；确定降级与人工介入方式；在模型中声明扩展点；确定投影清单和技术栈。

通过条件有三项：每个命令都有执行等级；涉及资金或不可逆的命令没有设为自动执行，或已记录理由；扩展点已在模型中声明。

## 决策

### 1. 每个命令的四类边界

- **业务**：所属聚合。
- **确定性**：作用于该命令的规则（拒绝 / 转人工 / 标记）及人工决策点。
- **人机**：执行等级，均沿用当前模型。
- **生成**：命令入口、前置状态检查、规则检查、事件均由模型生成；表中只列需要手写的扩展点。

| 命令 | 聚合 | 确定性：规则与人工决策点 | 执行等级 | 扩展点（手写） |
|---|---|---|---|---|
| 发起项目 PS 准备 | 任务 | 无 | 仅人工 | 无 |
| 取得并组装任务上下文 | 任务 | 拒绝：同一学生经历、同一学生英文定稿、知识已入库、项目与申请季对应；标记：要求未找到 | 执行后复核 | 上下文检索 |
| 准备项目中文稿 | 任务 | 拒绝：稿件经历属本学生；标记：未核对细节、要求未找到、缺选材理由；允许：无方向初稿 | 执行后复核 | 中文起草 |
| 录入学生对中文内容的确认 | 任务 | 拒绝：须明确确认当前中文版本 | 仅人工 | 无 |
| 依据确认中文生成英文 | 任务 | 拒绝：当前中文须已确认 | 执行后复核 | 英文生成 |
| 检查英文稿及依据 | 任务 | 拒绝：英文须对应已确认中文；超长不得记为通过；转人工：未知要求、长度计量不一致（对应两个人工决策点）；标记：要求未找到 | 执行后复核 | 英文检查 |
| 顾问最终确认 | 任务 | 拒绝：英文对应已确认中文、已检查当前版本、明确确认当前版本、已知要求须通过 | 仅人工 | 无 |
| 修订中文内容 | 任务 | 无 | 仅人工 | 无 |
| 修订英文措辞 | 任务 | 无（之后的检查与确认仍受上述规则约束） | 仅人工 | 无 |
| 记录具体核对问题 | 任务 | 无 | 执行后复核 | 无 |
| 记录人工核对结论 | 任务 | 人工决策点：背景差异、资料变化 | 仅人工 | 无 |
| 记录官网最低条件达标情况 | 任务 | 无 | 执行后复核 | 达标对照 |
| 记录未达标仍继续申请 | 任务 | 拒绝：只能在未达标时记录；标记：未达标事实保持；人工决策点：是否继续 | 仅人工 | 无 |
| 记录资料变化提醒 | 任务 | 无；由三条策略触发 | 自动执行 | 受影响任务定位 |
| 记录客户放弃申请 | 任务 | 无 | 仅人工 | 无 |
| 恢复申请 | 任务 | 无 | 仅人工 | 无 |
| 记录已递交 | 任务 | 无（只能在顾问已确认后执行） | 仅人工 | 无 |
| 记录顾问提供的学生上下文快照 | 学生上下文 | 无 | 仅人工 | 无 |
| 更新顾问反馈的学生上下文快照 | 学生上下文 | 无 | 仅人工 | 无 |
| 记录学校官方项目知识 | 项目知识 | 拒绝：只写入官网来源；没找到不得填值 | 执行后复核 | 官网抓取与抽取 |
| 同步学校官方项目知识 | 项目知识 | 同上；由每月同步策略触发 | 自动执行 | 官网抓取与抽取 |
| 记录顾问手动网申发现的差异 | 项目知识 | 无 | 仅人工 | 无 |

### 2. 自动执行与不可逆命令的审查

本场景没有涉及资金的命令。设为自动执行的只有两个：

- **记录资料变化提醒**：只为任务新增一条待评估问题，不修改稿件或状态，可由顾问处理关闭。
- **同步学校官方项目知识**：新版本另存，旧版本及差异保留，已被任务使用的版本不覆盖，可以回退；变化会提醒受影响任务。用户已确认差异直接生效。

业务上不可逆的命令是“记录已递交”（进入终止状态），为仅人工。审查结论：符合标准第 6.1 节，无需另记例外理由。

### 3. 扩展点

扩展点是模型无法完整描述、需要手写的部分（标准第 7.2 节）。生成器为每个扩展点生成接口或空实现，手写代码只能写在扩展点内。

| 扩展点 | 所属聚合 | 命令 | 做什么 | 类别 |
|---|---|---|---|---|
| 上下文检索 | 任务 | 取得并组装任务上下文 | 沿模型关系取得学生事实、素材、方向初稿、同一学生英文定稿、本项目及申请季的课程与要求 | 数据适配 |
| 中文起草 | 任务 | 准备项目中文稿 | 调用大模型起草中文稿，并记录选材理由 | 大模型计算 |
| 英文生成 | 任务 | 依据确认中文生成英文 | 调用大模型生成英文 | 大模型计算 |
| 英文检查 | 任务 | 检查英文稿及依据 | 长度按官网单位计量（确定性代码）；题目回应、事实一致、中英对应由大模型辅助判断 | 混合 |
| 达标对照 | 任务 | 记录官网最低条件达标情况 | 对照最低条件与学生背景；无法判断时保持未知 | 大模型计算 |
| 受影响任务定位 | 任务 | 记录资料变化提醒 | 按策略的目标范围找出未递交任务 | 数据适配 |
| 官网抓取与抽取 | 项目知识 | 记录 / 同步学校官方项目知识 | 抓取官网、结构化抽取要求与课程、与上一版比对差异 | 外部适配 |

**元模型调整**：聚合的 `extension_points` 目前是字符串列表，无法表达扩展点属于哪个命令、属于哪个类别。建议改为结构化条目，字段为名称、命令、用途、类别，并让校验器检查所引用的命令属于该聚合。本记录采纳后，再按模型变更流程修改元模型并在模型中声明上述扩展点。

### 4. 降级与人工介入

本场景不使用置信度评分，因此不设数值降级阈值。降级由以下明确情形触发：

1. **命中规范性规则**：按规则动作拒绝、转人工或标记，并记录命中的规则 ID 与模型版本（标准第 6.3 节）。
2. **上下文闭包缺失**：组装时缺少必需资料，报告缺少什么，记录核对问题，任务不推进（标准第 6.4 节）。
3. **扩展点失败**：大模型拒答或出错、官网抓取失败时，按配置重试；仍失败则记录核对问题交顾问。重试次数写在配置中，不写死在代码里，初始建议 2 次。
4. **规则与模型均未覆盖**：记录为核对问题交顾问判断，作为以后的规则候选。

人工介入方式：

- **人工介入队列**就是任务中的未解决核对问题，加上“执行后复核”命令的产出。主流程本身要求顾问确认中文录入和最终稿，复核自然发生在流程中。
- **驳回必须有理由**：解决问题时填写处理意见，修订中文和修订英文措辞时填写原因（命令已有该参数）。

### 6. 技术栈（业务系统，阶段 4 开始时最终确认）

- **语言**：Python，与现有生成器、校验器一致。
- **数据**：单用户、本机运行，使用本机数据库（如 SQLite），经实现映射与数据适配扩展点访问；学生资料只存本机。
- **大模型**：扩展点内经 Anthropic Python SDK 调用 `claude-opus-5-5`。
- **界面**：与问答 AI 同一个本机网页应用（ADR-003）。

## 备选方案及放弃理由

- **把“同步学校官方项目知识”保持为执行后复核**：更保守，但用户已确认差异直接生效；以保留旧版本、记录差异和提醒受影响任务控制风险。
- **不声明扩展点，直接在服务代码里手写**：违反标准第 7.2 节；生成代码与手写代码会混在一起，模型变化时无法列出受影响的手写文件。
- **引入置信度评分与数值阈值**：目前没有可校准的评分来源；先用明确触发条件，运行后有数据再评估。

## 后果与风险

- 大模型类扩展点（起草、生成、检查、达标对照）的质量只能在阶段 5 用评测和顾问抽查验证；模型结构正确不代表写作质量合格。
- 官网抓取要遵守学校网站的使用条款，频率为每月一次。
- 阶段 3 的“扩展点已在模型中声明”在元模型调整并写入模型前不算完成；本记录采纳后执行。
