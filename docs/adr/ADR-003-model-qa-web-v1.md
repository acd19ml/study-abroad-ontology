# ADR-003：网页问答 AI 第一版的运行框架与技术选择

- 状态：提议
- 日期：2026-11-02
- 相关模型元素：不新增模型元素；只读使用全部元素
- 依据：[问答 AI 范围](../proposals/model-qa-agent-v0.1.md)（用户已确认：只读、网页、阈值）；[ADR-001](ADR-001-semantic-service-and-harness-boundary.md)、[ADR-002](ADR-002-semantic-service-contract.md)；[评测问题集](../../evals/model-qa/README.md)。

## 背景

用户已确认第一版只读、在网页上使用，阶段 5 阈值为问答正确率不低于 90%、越界次数为 0。需要选定 Harness、大模型、网页形态、运行记录与评测方式。用户是唯一使用者，在自己的电脑上使用。

## 决策

### 1. Harness：Anthropic Python SDK 的 Tool Runner

使用官方 `anthropic` Python SDK 的 Tool Runner（`client.beta.messages.tool_runner`）运行工具循环。工具只有 ADR-002 的 S1–S6 六个只读能力，没有文件、命令行或联网工具。

选它是因为它只循环调用我们定义的工具，SDK 负责工具循环、重试和流式输出，不需要自己写循环；同时不附带任何可以接触代码仓或文件系统的内置工具，正好满足“不接入代码仓”。项目现有工具链是 Python，沿用即可。

Tool Runner 属于 SDK 的 beta 辅助功能，依赖版本需固定。

### 2. 大模型

- 使用 `claude-opus-5-5`，开启自适应思考，`effort` 先设为 `medium` 并显式写出；用评测结果调整，正确率不足再提高。
- 使用流式输出，网页逐字显示回答。
- 开启服务端回退（`fallbacks: "default"`）：主模型因安全分类拒答时，由 API 自动改用其他模型作答，避免顾问看到空回答。不需要可以关闭。
- 系统提示词只写回答格式与行为约束（范围草案第 3、4 节），不写任何业务规则。业务规则一律经工具取得。

### 3. 网页形态

- 本机运行的小型网页应用：Python 后端加单个聊天页面，只监听本机地址（`127.0.0.1`），单用户，不设登录。
- 页面显示回答正文、引用的模型依据（可点开看定义）、所用模型版本；依据可链接到模型浏览页 `generated/ps-model-explorer.html` 中对应的元素。
- 启动方式写入 README，一条命令启动。

### 4. 凭据

调用 Claude API 的凭据使用本机 `ant auth login` 登录状态或环境变量 `ANTHROPIC_API_KEY`，不写入仓库。

### 5. 运行记录

每次问答在本机记录一条，包括时间、问题、模型版本、调用的语义服务及返回的依据 ID、回答、用量。记录存放在不纳入 Git 的本机目录。满足标准第 6.5 节“每条运行记录包含模型版本”，也为以后的反馈演化（阶段 7）积累材料。

### 6. 评测方式

- 评测程序用同一个 Harness，不经网页，逐题运行 33 道题，保存回答与依据。
- 每题由大模型按 `key_points`、`must_not`、`evidence` 先做初判，再由顾问逐题确认；最终结果以顾问确认为准。
- 输出问答正确率与越界次数，与阈值比较。
- 每次评测都会产生 API 费用。首次运行前先估算费用并经用户同意。

### 7. 代码位置

| 内容 | 位置 |
|---|---|
| 模型知识包生成 | 扩展现有生成器 `tools/generator/`，输出到 `generated/` |
| 语义服务（S1–S6） | `src/semantic/` |
| 问答 Harness 与网页 | `src/qa/` |
| 语义服务契约测试（离线，不调用 API） | `tests/semantic/` |
| 评测程序与结果 | `evals/model-qa/` |

## 四类边界归属

问答 AI 不执行任何命令，人机边界为“只提供信息”。它不是模型中的执行角色，因此不新增角色元素；三期加入代操作时，再在模型中建模 AI 客服角色及其可执行命令。

## 备选方案及放弃理由

| 方案 | 放弃理由 |
|---|---|
| Claude Agent SDK | 自带读写文件、命令行等工具，能力远超只读问答，和“不接入代码仓”相冲突，还需额外限制权限 |
| Managed Agents（Anthropic 托管运行） | 托管的是带执行沙箱的长时运行 Agent；本场景工具都在本机，问答是短对话，用不上沙箱，反而增加会话管理。每月官网同步这类定时任务，阶段 4 可再评估它 |
| 把语义服务做成 MCP，接入 claude.ai 网页 | 无法控制系统提示词、运行记录和批量评测，且需要公网可访问的服务端 |
| 自己写工具循环 | 代码更多，Tool Runner 已满足需要 |
| 向量检索 / 知识库问答 | 模型只有百余个元素，结构化检索和沿关系取闭包已足够，向量检索反而让依据不精确 |

## 后果与风险

- Tool Runner 与回退功能为 beta，SDK 升级可能带来变化；固定依赖版本，升级时重跑评测。
- 大模型可能把用户描述错误转成规则判定的事实，导致判定错误；评测中的规则类题目用于发现这类问题。
- 只在本机运行，换电脑或给他人使用需另行决定部署方式。
- 第一版的“受限”依靠只读工具与回答约束。代操作上线前必须具备控制层（ADR-001 第 4 点），不能沿用本版做法。
