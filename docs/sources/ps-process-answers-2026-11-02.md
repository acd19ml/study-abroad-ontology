# PS 流程细节答复记录

- 日期：2026-11-02（Asia/Shanghai）。
- 背景：用户对 PS 准备流程中录入方式、客户放弃申请、官网同步、最终确认、递交记录和英文措辞修改等问题的答复。

## 第一轮答复

用户原话：

1. “实际是学生在微信里确认、顾问录入。从前端交互的角度来看，顾问操作该系统不需要附学生依据。”
2. “我没理解任务撤回/关闭，从申请的角度只有在递交申请之前的任意时间/进度节点客户表示不用申请该项目。”
3. “什么是官网知识库，如果指的是从官网获取的信息保存到本地知识库，这一动作需要每个月跑一次定时任务来同步差异并记录，不过要区分不同申请季。”

已确认的事实：

- **学生中文确认的录入**：学生在微信中确认，顾问在系统中录入；录入时不要求附学生确认依据。
- **客户放弃申请**：递交申请前的任何时间或进度节点，客户都可能表示不再申请该项目。这和未达官网最低条件时的继续或放弃选择是两件事。
- **官网信息同步**：从学校官网取得的项目信息保存到本地知识库，每月运行一次定时任务，同步差异并记录，按申请季区分。

## 第二轮答复（Q-074 至 Q-077）

用户原话：“应该被拦住、必须先改稿。 一样处理。不用记录原因，恢复原任务。同步库里全部项目，差异直接生效不过要记录差异变化，差异与学生正在准备申请的项目相关要提醒我。”

- **Q-077**：AI 检查发现稿件不符合已查明的要求（例如超出字数限制）时，顾问的最终确认应被拦住，必须先改稿。
- **Q-074**：顾问标记经历已核对、记录客户是否继续申请，与中文确认一样处理，不要求附依据。
- **Q-075**：客户放弃申请不用记录原因；之后客户又想申请时，恢复原任务。
- **Q-076**：每月同步库里全部项目；差异直接生效，但要记录差异变化；差异与学生正在准备申请的项目相关时，提醒顾问。

## 第三轮答复

用户原话：“我和客户会不断的进行稿件交付和反馈，中间会有很多版本，那么最终定稿的英文稿件即不需要再修改。学生补充或更正背景 也是我来提交，该系统目前不需要客户操作，仅由我“顾问”个人使用。 只要没递交，发生的变化都需要提醒。”

- **已审核 PS 的含义**：与客户反复交付、反馈后，最终定稿、不需要再修改的英文稿，就是可供其他项目参考的已审核 PS；不另设客户认可步骤。
- **系统使用者**：系统目前只由顾问个人使用，客户不操作；学生补充或更正背景也由顾问提交。
- **变化提醒范围**：只要还没递交，学生背景和项目要求发生的变化都需要提醒顾问，包括已最终确认的稿件。

## 第四轮答复（Q-078、Q-079）

用户原话：“按你的建议处理”。

- **Q-078**：顾问手动递交后，在系统中记录“已递交”；记录后不再提醒变化，也不再修改该项目的稿件。系统不操作网申。
- **Q-079**：客户只对英文措辞提意见时，可以直接出新的英文版本并重新检查；涉及经历内容的修改仍回到中文。是否涉及经历，由顾问判断。

## 第五轮答复：问答 AI

用户原话：“同意第一版只读，阈值按建议，用网页”。

- **问答 AI 范围**：第一版只读，只回答规则和操作问题；代查、代操作等业务系统建成后再加。
- **使用方式**：网页。
- **验收阈值**：问答正确率不低于 90%，越界次数为 0。
