- Q-071：衡量顾问主动投入时间和场景验收通过率；建议同口径对照用时减少至少 50%、首批确认案例全部通过、硬约束违反为 0。50% 和案例通过率是提议，不是已确认目标或已测能力。

- Q-073：建议用户担任规则负责人及业务验收负责人，待确认。

提出该轮方案时用户仅选定首场景，未确认其他条件。后续反馈如下，不再将上面的旧提案当作当前待采纳方案。

## R25 用户反馈与确认

- Q1 采用：接受首场景范围和文书准备边界，保留 AI 查库、官网补缺并入库的职责。
- Q2：用户认为用时减少 50% 难以量化，不理解“首批正常及主要异常案例全部通过”和“硬约束违反为 0”的表述；不能据此记录为已认可这些阈值。
- 用户明确成功标准：“我不需要主动去找编写ps时给ai的上下文”，包括项目课程、申请其他项目已经客户审核的 PS、客户背景材料、编写 PS 的标准；项目课程查官网后可入库。验收主要来源于向 AI 提问或下达指令，观察 AI 能否依据本体模型回答或操作。
- Q3 采用：保留优先使用历史案例的取样方式；结合 Q2 的反馈，不再要求为省时指标计时。实际历史样本与上下文准备现状仍未提供，不能填写基线数值。
- Q4 采用：用户担任规则负责人和业务验收负责人。

## 本轮整理及剩余项

- 场景画布撤下省时 50% 和未被采纳的案例通过率提案，改写为实际指令与可观察表现。
- Agent 提议用“仍需要顾问手动补齐的已有上下文类别数”记录现状，目标为 0 类；这是对用户目标的度量草案，具体口径待整体对齐，不是已测结果。
- “硬约束”用业务例子说明：不能把超过已知限制的稿件判为合格，不能把未核对内容当作已确认事实。示例字数不是实际项目要求。
- 当时提出先取得历史案例复盘；该推进建议已被后续用户纠正，不作为当前前置条件。阶段 0 尚未通过。

## 后续纠正：先验证本体模型，真实案例后置

- 用户认为当前尚不需要具体案例，希望先验证本体模型，指出模型不对时给真实案例也不能解决问题，并要求解释阶段 0 到阶段 2 的关系。
- 当前优先级调整为：收口场景目标与边界，整体审阅已有业务发现内容，再验证模型的概念、关系、状态、规则和推理依据是否正确。
- 真实学生资料不作为当前必须提供的前置条件。可用已确认规则和明确标注的假设情景检查模型；不将假设数据当真实客户事实或实际学校要求。
- 标准阶段 0 确实要求至少一个带基线的指标和验证阈值，但没有规定必须用真实学生案例获得；Agent 先前把历史案例复盘这种候选方法说成了必要条件，应纠正。
- 建议用“关键业务问题能否从模型中得到完整、可追溯的回答依据”组织模型验证。指标、基线及阈值的正式对应方式仍待确认，不因取消案例前提而虚构阶段通过。
- 模型验证不代替后续系统验证：模型阶段核对表达、关系、规则与允许的判断；具备实现后再验证真实资料检索、官网读取、稿件质量和实际操作。
